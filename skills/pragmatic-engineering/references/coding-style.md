# coding style
Strict types, ESM, semicolons, double quotes, camelCase filenames. Prefer type aliases; interfaces for contracts. Prefer default exports for primary symbols, named exports for related groups. Native getters (`get name()`) rather than `getName()`. Use public readonly when a getter adds no value. Private fields use `_name`. Standalone functions use arrow syntax; class methods use ordinary methods unless binding is needed. Prefer const, inference, destructuring, async/await, optional chaining, nullish coalescing, spread, import type, satisfies and as const where clear. Never use any to evade typing; narrow unknown. Avoid unsafe assertions, needless generics and clever chains. Comments explain why, constraints or complex logic.
