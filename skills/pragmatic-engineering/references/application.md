# application
Always separate commands and queries logically, without requiring separate databases, buses or event sourcing. Group related operations in cohesive classes. Application validates boundary input; domain protects invariants. Adapt dependency injection to framework and dependency count; avoid global mutable business configuration. Return entities internally or DTOs at boundaries as appropriate. Group DTOs by responsibility. Ports only for real boundaries; no mirrored interface for each class. Mappers only when representations differ. Use transactions and Unit of Work where atomicity requires coordination; scope repositories to the transaction. Queries must not mutate business state.

Keep orchestration readable: extract reusable application preconditions into cohesive guards when justified. Repository-dependent checks belong to application, not pure domain rules; perform checks and writes within appropriate transactional/concurrency guarantees. Validate input shape at the boundary and preserve entity invariants independently. See [guards and rules](guards-and-rules.md).
