# project structure
Use camelCase.ts names except required framework conventions and config/test suffixes. Group related types, interfaces, classes and functions by responsibility. Review files from 300 lines; over 500 requires explicit justification. Limits are advisory. Keep directory depth minimal. Centralize utilities from the start in one clearly owned shared location; do not move domain rules there or create empty folders. Use index.ts in every source-code folder; expose intended exports explicitly, avoid cycles, and use direct internal imports where needed. Never export tests or secrets through barrels. Search for existing implementations before writing code. Extract duplication only when it represents the same responsibility.
