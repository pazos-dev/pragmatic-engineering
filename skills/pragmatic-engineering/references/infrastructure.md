# infrastructure
Prefer concrete repositories implementing meaningful contracts; generic repositories only when behavior is genuinely shared. Mappers are arrow functions when needed. CQRS persistence may share implementations while keeping responsibilities distinct. Select ORM or SQL by requirements. Wrap external libraries only at a real boundary. Centralize typed validated configuration; inject when appropriate. Default to shared process-level connection pools; never share request state or transaction context. For reusable libraries, host controls dependencies and lifecycles. Singleton implementation adapts to need. Preserve constraints, concurrency, isolation and error causes. No business rules or ORM types leaking into domain.
