# testing
Prefer Vitest. TDD for complex logic and bug fixes. Test observable behavior, invariants and failure paths rather than private implementation. Test descriptions in Spanish. Hybrid layout: unit tests alongside code; integration and E2E under tests. No mocks or spies; use real implementations and functional fakes. Use isolated real databases for relevant integration tests. Contract tests mandatory for multiple adapters of a contract. No arbitrary coverage threshold; prioritize critical behavior. Run only affected tests; report scope and unrun checks. Never delete failing tests, weaken assertions, access private fields or use any to bypass typing. Keep tests deterministic and independent.

Test reusable rules with valid, invalid and boundary values where meaningful; verify guards throw the correct custom error, and entity operations reject invalid changes without mutating state. Avoid duplicating every rule scenario at every layer; keep representative entity invariant tests. Verify application checks with real adapters or functional fakes and test database constraints/concurrency using isolated real databases where relevant. Spanish descriptions; no mocks.
